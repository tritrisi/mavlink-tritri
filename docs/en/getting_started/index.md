# Getting Started

TRITRI is a standard MAVLink 2 dialect: `tritri.xml` includes `military.xml`,
which includes `common.xml`, so any MAVLink 2 toolchain can consume it.

## Use the pre-generated C library

Pre-generated C headers are published to
[mavlink-tritri-c_library_v2](https://github.com/tritrisi/mavlink-tritri-c_library_v2)
and regenerated by CI on every change to `military.xml` / `tritri.xml` on
`main`. Add it as a submodule and include the dialect header:

```sh
git submodule add https://github.com/tritrisi/mavlink-tritri-c_library_v2.git mavlink
```

```c
#include "mavlink/tritri/mavlink.h"
```

See the [MAVLink C library guide](https://mavlink.io/en/mavgen_c/) for how to
pack, send, and parse messages.

## Generate bindings for another language

Generate bindings with [mavgen](https://mavlink.io/en/getting_started/generate_libraries.html).
Because the dialect XMLs include upstream definitions by relative path, place
them next to `common.xml` first:

```sh
git clone https://github.com/mavlink/mavlink.git --recursive
cp military.xml tritri.xml mavlink/message_definitions/v1.0/
cd mavlink
python3 -m pymavlink.tools.mavgen \
  --lang=C --wire-protocol=2.0 \
  --output=out message_definitions/v1.0/tritri.xml
```

Or use the helper in this repository:

```sh
./scripts/generate.sh
```

Replace `--lang` with any language mavgen supports (for example `Python3`,
`CS`, `Java`, `TypeScript`).
